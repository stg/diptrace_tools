JLCPCB BOM Editor
==================

Help -> How to use opens HELP.txt, a brief guide for new users. This README
keeps the detailed behavior reference. Help -> Normalization rule reference
documents the configurable language; Tools -> Open normalization rules opens
this program's rules JSON. Defaults preserve the existing assembly results.
Keep the Shared folder beside JLCPCB_BOM; both the desktop editor and CLI use it.
Tools -> Open AI check settings opens ai_check_settings.json. Its
instruction_lines list supplies the leading AI prompt in checker .txt output
and is re-read on every run. Defaults preserve the previous instruction text.
Format/source notes remain generated by the checker. Invalid settings stop
the check before downloading or replacing reports.

Windows: double-click "Launch JLCPCB BOM Editor.cmd".
macOS: use "Launch JLCPCB BOM Editor.command".
Linux: run sh "Launch JLCPCB BOM Editor.sh".
Then choose any .dchxml schematic. See the root README.md for setup.
The app reopens the last schematic on launch. If it is unavailable, the opening
picker uses the last selected schematic folder. An explicit command-line file
overrides the remembered file. File -> Open Recent lists the last 10 schematics.
Window size/position, column widths, and the grid/log split are remembered on exit.
Alternatively:
    python bom_editor.py "D:\path\Board.dchxml"

Dependencies:
    python -m pip install -r requirements-editor.txt

Files and truth
---------------
Opening Board.dchxml loads Board.json beside it, or creates that JSON from the
schematic when it is missing. Existing BOM_modified.csv files are not imported.
The JSON stores grouped RefDes, Name, Value, Pattern and LCSC Part # rows, with
schema_version 1 and output_folder ./order (relative to the schematic).

The schematic BOM is obtained from placed normal component instances; net ports
and power symbols are excluded. Patterns are resolved through the component and
pattern library links. Multipart symbols are counted once by designator.
Grouping uses exact Name, Value, Pattern and LCSC values, with natural designator
order. Empty Name or Value fields remain empty.
Multipart components use the main unit (lowest ComponentPart) for BOM fields;
other units may have different display text without causing a load error.

Grid
----
Left: current schematic Name, Value and Pattern (read-only).
Middle: JSON Name, Value, Pattern and LCSC are editable.
Right: current output values when available from BOM XLS,
otherwise the converted JSON preview. Blank output values remain blank. Grouped
rows with differing actual values show (mixed); hover for per-designator values.
Alternate dropdowns remain the component selection for the next generation.

Case-only differences between schematic and JSON Name, Value, and Pattern are
ignored for highlighting. Stored text retains its original case.
Input Name/Value differences are red. Pattern differences are red when both patterns
match recognized package names: RES/CAP/IND/DIO with an optional underscore then a four-digit size,
or R/C/I/D with an optional underscore then a four-digit size. Any underscore
suffix after the size is optional and must contain exactly one letter (_N, for
example). Matching is case-insensitive. Differences involving an
unrecognized pattern are yellow. Added JSON Value suffix words are also yellow
when all original words match: input 1u 16V versus JSON 1u 16V X5R, for example.
Changed/removed original words remain red. Added suffix words, including DNP or
DNM, are yellow when the original value words are retained.
Standalone DNP or DNM in Name or Value omits the component from output.
Markers are case-insensitive and bounded by spaces, tabs, slashes, or start/end of text.
Output footprint conversion uses these same recognized package rules: IND_0603,
RES0603_N, and other recognized forms become just their four-digit size (0603).
Red output cells differ from the current BOM
XLS, or are missing. Hover a cell for the actual per-designator values and
current file contents and expected preview. DNP/DNM previews are marked as omitted;
current output values remain visible if the row has not yet been removed. They are red only
when they are still present in an output. The preview compares values, not row
order or file timestamps.
Input Name comparison marks compatible extra trailing suffixes in the JSON Name
as yellow warnings and treats
each lowercase letter in the input Name as one letter placeholder. For example,
COMP12x34 accepts COMP12A34TR. Blank input names still differ from nonblank JSON
names. This affects input highlighting only; values and generated outputs retain
their existing comparisons, and saved names remain unchanged.

Select a grouped row and press Expand selected group to split it into individual
designators in place. Editing a grouped row updates all its designators. Expanded
rows stay expanded during editing/saving. Reload reads both files and recombines
identical rows. Reload/Open ask before discarding unsaved edits. Close offers
Save/Discard/Cancel. Ctrl+S saves JSON; Ctrl+O opens a schematic. Ctrl+F focuses
the existing filter and selects all its text for replacement.
Ctrl+Z undoes content changes. Ctrl+Y or Ctrl+Shift+Z redoes them. Edit also has
Undo/Redo commands. Each grouped cell edit, Use input operation, or LCSC import
is one undo step. Undo/redo updates the grid and unsaved-state indicator only;
it does not undo saves, generated files, or schematic back-annotation. Open/Reload
clears history. A new content edit clears redo history.
File operations are in File; group expansion and copying input values are in
Edit; schematic sync, output generation, and LCSC workbook actions are in Tools.
Save JSON is in File (Ctrl+S). Expand selected group, Compact identical, and
Generate outputs have quick buttons. Compact identical recombines matching grid rows immediately,
without reloading files or discarding edits. Outputs are grouped independently of
whether the grid is expanded.
The grid uses a compact row height.
Click a column heading to sort naturally (for example, 2 before 10). The newest
column becomes primary; previous columns remain secondary, preserving order
within ties. Click the primary heading again to reverse its direction. Header
numbers show priority: [1] is primary, [2] secondary, and so on. For example,
clicking Pattern followed by Value sorts by Value first and Pattern second.
Sort priorities and directions are remembered across reloads and launches.
Right-click an indexed column header for Remove sorting. Other sort priorities
are retained and renumbered. Removing the last sort keeps the current row order.
Edit -> Copy selected rows (Ctrl+C) copies displayed columns as tab-separated
text, including the selected alternative shown in an output dropdown.
Input/JSON Value and numeric Output Comment sorting uses scaled numeric magnitude:
1, 2.2, 10, 100; 100pF < 1nF < 100nF < 1uF. Micro accepts µ, μ, or u; m and M
remain distinct. All standard SI prefixes from q (10^-30) through Q (10^30) are
supported, including da/h/d/c and f/a/z/y/r/q and T/P/E/Z/Y/R/Q. Units (Ω/R, F,
etc.), embedded notation (4k7, 2u2F, 4R7), and scientific notation are recognized.
Equal magnitudes preserve the previous sort even if their spellings differ.
The SI prefix list is shared by sorting and output conversion. Embedded output
values support these same prefixes (for example 2n2F -> 2.2nF, 1G5R -> 1.5GΩ).
Lowercase f/m/r remain SI prefixes; uppercase F/R are unit markers where used
as trailing units. R between resistor digits is a decimal marker (4R7 -> 4.7Ω).
Explicit resistance values such as 0R, 1k5R, or 0Ω on non-R/C designators are
also normalized to Ω; for example a zero-ohm link designated L5 outputs 0Ω.
The CLI axon_bom_outputs.py and this UI use the same bom_conversions.py helpers.
The actual CLI lives in the tool folder and imports helpers from its own script
location. Its project data defaults to the current working directory; use
--project D:\Sync\ExternalProjects\DSDUC\pcb to select a project explicitly.
Existing --original/--current/--changes/--suffix/--xls arguments remain supported.
Legacy project launchers may still refer to the previous installation folder.
Run this tool's CLI directly when using the renamed JLCPCB_BOM package.

Use input -> JSON copies Name/Value/Pattern for selected rows from the schematic.
Saved JSON Pattern edits survive Reload and determine the output footprint.
New schematic components are added
from the schematic; JSON-only designators are retained and flagged as missing
from the schematic, so their edits are not silently lost.
To remove components deleted from the schematic, Reload first, then right-click
the affected row and choose Remove missing from JSON. This removes only row
designators absent from the loaded schematic, preserving any still-present
designators in a mixed group. The operation supports undo/redo, including complete
alternate lists and output selections. Save JSON to persist the removal.

Back-annotate to schematic writes only instance Name and Value. It makes a timestamped
.bak first, validates the XML, and preserves the rest of the XML text. It refuses
to sync if the schematic changed on disk since opening; Reload first. LCSC stays
in JSON. Pattern and designators are never written to the schematic.
Tools -> Back-annotate to schematic has two modes. All retains the existing
behavior: changed JSON Name/Value fields update every symbol unit; fields equal
to the main symbol remain untouched. Errors only uses the same behavior but skips
yellow Name or Value suffix differences. Both modes exclude Pattern and LCSC and retain
the timestamped backup behavior.
Right-click a grid row for Expand, Back-annotate all, Back-annotate errors,
or Use input -> JSON. Use input -> JSON copies current input Name, Value,
and Pattern into primary JSON fields with undo/redo support. JLCPCB part numbers,
alternates, and output selection are preserved.
These actions affect only that row's designators (all occurrences in a grouped
row). Expand is available for grouped rows; expand first to target one occurrence.

Alternates
----------
Right-click a row and choose Edit alternates to edit Name, Value, Pattern, LCSC
number, and Notes in a separate window. Add alternate starts with the primary's
Value and Pattern. Apply commits the edits to the main editor; Save JSON writes
them to disk. Closing the alternate editor with unapplied edits asks before
discarding. Removing the selected alternate switches output back to the primary.

Output Component replaces Output Comment. With no alternates it shows plain
current output comment text (or preview if no output row exists). With alternates it is a dropdown showing the primary name and
Alt: name for each alternate; unnamed parts use their converted comment.
JLCPCB part numbers and component details are in option tooltips. Current file comments
and expected comments are in the tooltip. The selection controls generated output
Comment, Footprint, and LCSC, including
DNP/DNM omission. A selected alternate and its output cells are flagged yellow,
including differences from current output files; the status still says Generate
needed when files need updating. Primary output mismatches remain red. Schematic
mismatches against primary JSON fields retain their normal highlighting.
Filter searches alternates too.

Alternate edits and output selection support undo/redo and the unsaved-JSON warning.
JSON rows store an Alternates list and Output selection (0 = primary, 1 = first
alternate, etc.). Existing JSON without these fields uses the primary. Different
alternate lists or selections prevent rows from compacting together. Group edits
apply to every occurrence; expand a group first to target one designator.
Back-annotation uses the primary; assembly BOM XLS and the right-side preview
use the selected component with the shared conversions.

Generate outputs
----------------
Saves JSON and writes directly inside the JSON output_folder:
    Board_BOM.xls                 real legacy Excel workbook
    Board_CPL.xls                 converted from the required source CPL CSV

The UI creates no BOM CSV intermediates or legacy modified/changes CSV exports.
It uses .dchxml for source data, JSON for edits and selected components, and the
source CPL CSV for placement data. Existing BOM.csv, BOM_modified.csv,
BOM_original.csv, and BOM_changes.csv files are ignored and left untouched.
The right-side grid reads back only the BOM XLS. The CPL is searched only beside
the schematic.
The expected CPL source is Board_CPL.csv. To override its filename, add
"cpl_file": "MyPlacements.csv" to the project JSON and Reload. The overridden file
must also be beside the schematic; folder paths are not accepted. The default XLS output
name is Board_CPL.xls; bom_file and cpl_output_file override output filenames. Missing CPL files stop generation, reporting the
expected filename. Both source coordinate headers must specify their units:
mm, in/inch/inches or mil/mils. Inch/mil values are converted in memory to mm
before placement corrections. Generated X/Y coordinates use three decimal
places by default (cpl_decimals in project JSON). Unspecified/unknown units
and missing required RefDes/Designator, Side/Layer or Rotation headers stop
generation before saving or replacing output files. Column order may vary.
Generated CPL XLS includes only designators present in the generated assembly
BOM rows in memory, following the selected components and DNP/DNM omission. The source CPL CSV
is untouched. Generation reports excluded designators and warns if a BOM
designator has no placement in the source CPL; missing placements are not invented.
Duplicate included CPL designators stop CPL generation with an error. The UI and
CLI generator share this CPL filtering logic and assembly BOM conversion rules.
The legacy CLI still supports its original CSV exports; the desktop UI does not
depend on them.
Existing output files with these names are replaced by Generate.

CPL footprint corrections
-------------------------
Tools has a separate section with Open project settings JSON and Open place correction
file. Both open the JSON in the system's default application. Opening project
settings with unsaved grid edits offers Save or Cancel first; Reload after editing
project settings. Place correction changes apply at the next generation without
Reload. The place correction file can be opened without a loaded project.
The program database cpl_adjustments.json, next to bom_conversions.py, applies to
all projects and is re-read on every generation by both UI and CLI. It contains:
    {
      "schema_version": 1,
      "footprints": {
        "SOIC-16/150mil": {"rotation_deg": 90, "x_mm": 0, "y_mm": 0},
        "SOT23": {"rotation_deg": 180, "x_mm": 0, "y_mm": 0}
      }
    }
Footprint keys match the generated BOM Footprint exactly, ignoring letter case
and surrounding whitespace. This is the selected output component's footprint,
including alternates and simplified package names. Add rules by adding footprint
entries; any omitted rotation_deg/x_mm/y_mm field defaults to zero.
Offsets are added to source rotation/X/Y. Every output rotation is wrapped to
0 <= angle < 360 degrees, including negative angles and footprints without a
correction rule (-90 -> 270; 360 -> 0; 450 -> 90). X/Y offsets are in mm. Each matching placement is adjusted,
regardless of layer. Source CPL CSV and schematic files are not changed. Every
generation starts from the source CPL, so corrections never accumulate. Unmatched
footprints receive no correction. Invalid database fields/numbers are errors.
The generation log lists designators whose placements were corrected.

LCSC workbooks
--------------
The JLCPCB-number import opens a picker for .xls/.xlsx. Workbook content is detected, so
JLC OOXML workbooks with an .xls suffix also work.

JLCPCB part numbers from XLS(X): accepts the simple JLC BOM table and the BOM Matching /
Assembly Order table. It maps by designator and chooses the last JLCPCB Part #
column (the selected match). Missing JSON numbers are filled; every conflicting
existing number gets a Replace primary / Add as alternate / Skip dialog once per
identical component group and incoming LCSC number, listing affected designators.
Different incoming numbers within a group receive separate decisions. A number
already present in the primary or alternate list is left alone. Add as alternate
keeps the current output selection and copies primary component fields with a
review note; edit those fields if the substitute differs. Blank workbook numbers do
not clear existing JSON assignments. Import edits are saved with Save JSON.

Check with AI uses a temporary snapshot of the current project, including unsaved
edits, chosen alternatives and notes. It needs no workbook or placement CSV and
does not save or back-annotate the project. Parts are selected, grouped, normalized
and excluded exactly as for Generate; descriptions include footprints and designators.
Unassigned parts are marked for review. Notes are attached after // only when present.
The bundled jlcpcb_bom_checker.py runs in a background process. Preparation stages
use an animated progress bar, followed by download/scrape progress. Stop check cancels.
Success opens the AI instruction/report text in the default system text editor;
the user supplies it to an AI assistant to perform the comparison.
Reports use the project's output folder and ai_check_file (default {stem}_AI_Check.txt),
with a companion .rohs.txt report. Non-RoHS warnings list exact designators.
Product HTML and JSON are cached in the bundled tool's lcsc folder across projects;
missing legacy cache files are copied from the project's lcsc folder without removing
or replacing existing files. The desktop command always uses the bundled checker;
legacy checker_script settings have no effect. The standalone checker retains its
legacy workbook/CSV CLI input for compatibility, outside the desktop workflow.
